# Fidelity Review: faithfulness, numerics provenance, conversion, hub

Reference for dimensions D5, D20, D21 of `REVIEW_DIMENSIONS.md` — the checks that tie the port to the original implementation and the checkpoint to the hub. These are the highest-consensus gaps mined from maintainer reviews (three of four reviewers each).

## D5 — Faithfulness to the reference implementation

The source-of-truth tenet has a mechanical form: every numeric expectation must have a provenance, and every rewrite of reference math must be justified.

- **Expected-value provenance.** For each integration-test slice, decoded text, or logits tensor: where did the value come from? Acceptable: generated by the original implementation (stated, ideally with the generation script or a hub-hosted fixture); computed in this conversation from the original repo. Not acceptable: values produced by the port itself (the test then proves the port equals the port). A test whose expectations have no stated provenance is a finding — ask "do these come from the original implementation?"
- **Parity tolerance.** Logits match the original at 1e-3/1e-4 for same-dtype comparison. Larger tolerances need the stated cause (dtype mismatch, known op difference). A cosine-similarity-only or argmax-only comparison where full-tensor comparison is possible is a weaker-than-required test.
- **Rewritten math.** A reimplementation of an op that exists upstream (or in a sibling model: GDN in qwen3_next, RoPE variants) either matches the reference form or carries a numeric justification. "Any reason we rewrote this?" is the review question; the burden is on the diff.
- **Debugging aid.** When parity cannot be traced (hidden upcast somewhere in a deep stack), point the author to `src/transformers/model_debugging_utils.py` — per-layer output dumps on both sides localize the divergence. Recommend it instead of accepting "close enough".
- **Run the snippet.** Usage examples in docstrings/docs of the PR are executed when a checkpoint is public; a snippet that errors is a finding with the traceback.
- **Visible deviation from provenance.** When an expected value must deviate from the reference output (fp-precision drift), the reference constant stays verbatim and the expected value is derived through explicit commented `.replace()`/delta edits next to it; silently editing the reference constant is a finding — the deviation must be diffable.

## D20 — dtype/cast provenance

Any added or removed cast in numerically sensitive code (RoPE, routers, attention softmax, normalization, linear-attention kernels) cites its source: the reference implementation line, a parity trace, or a sibling-family convention. 

- A removed upcast ("are we sure? they are downcasting here") and an added `.float()` are the same finding shape: no cited provenance → finding.
- **Quantization-safe multimodal casts.** Casting inputs to `module.weight.dtype` (the vision-tower/conv/patch-embed idiom) breaks under quantization — quantizers replace linear weights with non-float dtypes, and `getattr(module, "compute_dtype")` fallbacks are the same trap. Cast multimodal features to `inputs_embeds.dtype` at the scatter step, guarded on the embedding dtype being floating point, mirroring the image/video path.
- Cast decisions diverging from the model family's convention (other PP-family models call `.float()` before resize; this one branches) are findings even when locally defensible — numerics must not depend on unrelated flags.
- fp32 boundary arithmetic in rewritten positional-encoding code can shift a bucket index by one; when rewriting code the checkpoint was trained against, expect a fast path returning the original parameter at the training shape.

## D21 — Conversion scripts and hub checkpoint strategy

- **Script format.** `convert_*_to_hf.py` is a declarative weight-mapping dict (the mllama / dinov3_vit format: `ORIGINAL_TO_CONVERTED_KEY_MAPPING` regex dict), not imperative per-key rename functions (`create_rename_keys`-style). Imperative scripts are findings.
- **Registry first.** Pure renames belong in `conversion_mapping.py` (on-the-fly, no script needed); the script exists only for structural surgery the registry operations cannot express. A script doing only renames is a finding (see also `mechanisms_review.md`, Conversion-mapping registry).
- **Conversion-time transforms over runtime.** A weight permutation/de-interleaving executed on every forward moves into the conversion mapping (`PermuteForRope`-style converter) unless the runtime layout is semantically load-bearing — pay the cost once at load, not per step. Note `PermuteForRope`'s direction changed in #47517: before it, the operation on main permuted *back from* the block-split llama format; it now goes the usual way, into it. Read the current implementation before judging a permute orientation, and do not compare against a pre-#47517 checkout. `VisionFuseAndPermute` is expected to be replaced by the corrected rope conversion plus `Chunk(dim=0)`; new code depending on it is worth a question.
- **Verification in the script.** The conversion path verifies logits against the original implementation (`verify_logits` or equivalent) before pushing. A conversion with no numeric check is a finding.
- **Hub strategy.** Converted checkpoints and configs are pushed to a hub org — the author's org first, moved to the model owner's org later, or a hub PR on the original repo (`revision="refs/pr/N"`). A weightless or config-less release (bare `whatever.safetensors`) is handled with `transformers_weights` in the config or a hub PR, not with loading hacks in the library. Original checkpoint URLs recorded in the script stay (provenance).
- **Hub-merge gate.** Docs, tests, and config docstrings that reference hub artifacts still living on unmerged hub PRs block merging: either the hub PRs merge first or every reference pins `revision="refs/pr/N"`. State it as a pre-merge condition in the review.
- **Hub config type drift.** Config values on the hub can carry the wrong JSON type (`3.0` where an int is meant); strict type validation then rejects a working checkpoint. When a config field's type is loosened in the diff, check the actual hub `config.json` value — the fix may belong on the hub, not in the code.
- **Original sources stay reachable.** Do not accept removal of the original-repo download paths from a conversion script; they are the reproducibility trail.
